# IWSN Flagship V3 – production implementation and visual acceptance

**Date:** 28 November 2026
**Status:** Implemented and tested in isolated local Next.js worktree. Publishing to Softgen remains a separate verified action.

## Design basis

Selected 20-screen flagship design (desktop and mobile): plum/burgundy editorial hero, warm cream content, rose-pink accents, Swiss regional imagery, contextual Xenia, and a direct three-choice mobile path. This is a **real Next.js Pages Router implementation**, not the earlier self-contained HTML design board.

**Brand**: Deep plum `#210E21`, burgundy `#4B1733`, warm cream `#FFF8F6`, accent pink `#E72664`. Hero imagery and category/region illustrations reuse the project's existing editorial brand assets; no imaginary person is substituted for a real provider photograph.

## Xenia and data provenance

- Desktop header has Xenia/Inserieren/Anmelden; mobile bottom nav includes **Start / Suche / Xenia / Regionen / Konto**.
- Three-step touchscreen guide: **Wo → Was → Wann**, with automatic transition after each choice. Budget is optional on the summary screen.
- The guide calls the existing count-only catalogue endpoint and preserves an existing visitor's filter context. Tested interaction `Zug → Massage & Tantra → Flexibel` returns `/search?canton=ZG&category=massage`.
- Xenia is a **functional rule-based local guide**, not a newly connected LLM agent. It does not claim bookings, paid transactions, verified identities or availability without a current confirmation.
- The server-side paginated catalogue, source-media trust rules, RLS policies, saved selections and claim/payment restrictions remain in the existing architecture. No profile or database records are created by this design branch.

## Release boundary

**The new V3 code is not yet public until GitHub and the existing Softgen project deliver it.** A local production build does not establish the authenticated Softgen project's deployed revision or publishing rights. Do not create a second database or delete the existing managed tables. Before publishing, check GitHub CI, the exact main commit, Softgen's code revision, previous rollback, source/provider media rights, and then run the live 20-route smoke and mobile flow. Verify the new homepage headline and navigation on the public origin rather than merely checking HTTP 200.

Potential follow-up product work (separate from this visual implementation): actual conversational Xenia agent, complete provider verification/rights workflow, real intake end-to-end, performance field measurements, and full localization across legacy routes.
